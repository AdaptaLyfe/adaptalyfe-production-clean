Fix the **Your Dashboard → Customize** skill module customization issue in the existing Flutter application.

### Current Issue

In **Your Dashboard → Customize**, users can enable/disable skill modules.

Current behavior:

1. User opens **Your Dashboard → Customize**.
2. User enables a previously disabled skill module OR disables an enabled skill module.
3. User saves the customization.
4. User is redirected to **Your Dashboard**.
5. The Dashboard does **not immediately reflect the updated customization**.
6. Sometimes the old skill modules are still displayed.
7. When the user reopens Customize, closes it, or navigates back and forth, the correct configuration may eventually appear.

### Required Fix

Make the customization state update **immediately and consistently**.

When the user enables/disables a skill module and saves:

* The updated enabled/disabled state must be persisted correctly.
* Navigate back to **Your Dashboard**.
* Dashboard must immediately show the latest customization.
* Enabled modules must be visible.
* Disabled modules must not be visible.
* Do not require the user to reopen Customize multiple times.
* Do not require app restart.
* Do not require navigating away and coming back.
* The state must remain correct after leaving and reopening the Dashboard.

First inspect the existing implementation and identify:

* Customize screen

Do **not** create a completely new architecture.

Use the existing architecture and state-management pattern.

* Emit a new state after customization is successfully saved.
* Refresh/reload the Dashboard skill modules when returning from Customize.
* Make sure the Dashboard rebuilds when the customization state changes.

If the app uses another state-management solution, follow the existing implementation instead.
