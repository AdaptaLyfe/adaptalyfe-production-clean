In the existing React Native + Wrapper project, fix the Sleep Routine navigation and Log Sleep behavior.

### Bug

Path:
**Sleep Routine → Overview → Log Sleep**

Currently, when the user clicks **"Log Sleep"** from the Sleep Routine Overview screen:

* It redirects to the **Log Sleep** tab.
* But an already existing sleep log is automatically opened in **Edit mode**.
* Because of this, the user cannot create/add a new sleep log.

### Required behavior

When the user clicks **"Log Sleep"** from the Sleep Routine Overview:

1. Navigate to the **Log Sleep** tab.
2. Open the screen in **NEW/ADD mode**, not Edit mode.
3. Show empty/default fields required for creating a new sleep log.
4. Do NOT automatically load an existing sleep record.
5. The user must be able to enter new sleep information and save it as a new record.
6. Existing sleep logs must remain unchanged.

### Important distinction

There must be two separate flows:

**Add New Sleep**

* Overview → Click **Log Sleep**
* Open Log Sleep screen in `ADD/CREATE` mode.
* No existing record ID should be passed.
* Do not populate the form from an existing sleep log.
* Save should create a NEW sleep record.

**Edit Existing Sleep**

* User selects an existing sleep log.
* Open Log Sleep screen in `EDIT` mode.
* Pass the selected sleep log ID.
* Load that specific record.
* Save should update the existing record.

### Root-cause investigation

Before making changes, inspect the existing code and identify why the Overview's **Log Sleep** action is triggering edit mode.

Check:

* Sleep Routine Overview screen
* Log Sleep tab/screen
* Navigation/router configuration
* Navigation parameters
* Sleep log ID being passed during navigation
* `isEdit`, `editMode`, `mode`, `sleepLogId`, or similar state/params
* `useEffect`/initialization logic that loads an existing sleep record
* Shared state/context/store used by Sleep Routine
* Wrapper navigation handling, if the Wrapper controls or modifies the route
* Any default selected sleep log logic

Do NOT simply hide the existing data. Fix the actual navigation/state logic causing the wrong mode.

### Prevent regression

Make the add/edit mode explicit.

Use a clear distinction such as:

* `mode: "create"`
* `mode: "edit"`

or the equivalent pattern already used by this project.

When navigating from Overview using **Log Sleep**, explicitly open:

`mode = create`

and ensure:

`existingSleepLogId = null/undefined`

When editing an existing log, explicitly open:

`mode = edit`

with the correct existing sleep log ID.

Do not rely on the presence/absence of cached data or previously selected records to determine the mode.

### Form initialization

Make sure the Log Sleep screen resets correctly when opened in Create mode.

Create mode:

* Clear previous sleep log data from the form.
* Apply only the intended default values.
* Do not reuse values from the previously edited sleep log.
* Do not automatically fetch an existing sleep record.

Edit mode:

* Load only the selected sleep record.
* Populate the form with that record's data.

Also handle navigation from Edit → Create correctly. If the user edits a sleep log and then goes back to Overview and clicks **Log Sleep**, the previous edit state must not remain active.

### Save behavior

Create mode:

* Save = CREATE a new sleep log.
* Do not call the update API/action with an old sleep log ID.

Edit mode:

* Save = UPDATE the selected sleep log.
* Do not create a duplicate record.
