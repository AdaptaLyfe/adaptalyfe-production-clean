In the existing Flutter project, fix the **Sleep Routine → Overview → Log Sleep** flow completely.

### Current Bug

When the user is on:

**Sleep Routine → Overview**

and clicks **"Log Sleep"**, the app redirects to the **"Log Sleep"** tab, but it automatically opens the most recently/last logged sleep record in **Edit Mode**.

Because of this, the user cannot easily create a new sleep log.

The same issue happens when opening the **Log Sleep** tab directly: the latest sleep log is automatically loaded into edit mode.

### Required Behavior

Implement the following clear create/edit behavior:

#### 1. Clicking "Log Sleep" from Overview

When the user clicks **"Log Sleep"**:

* Navigate to the **Log Sleep** tab.
* Open the Log Sleep form in **Create/New mode**.
* Do NOT automatically load the latest/recent sleep record.
* Do NOT automatically open the previous sleep record in edit mode.
* The form should use the appropriate default date (normally today).
* The user should be able to enter and save a new sleep log.

#### 2. Selecting a Date With NO Existing Sleep Log

When the user selects a date:

* Check whether a sleep log already exists for that date.
* If NO sleep log exists:

  * Open the form in **Create Mode**.
  * Keep the form fields empty/default as appropriate.
  * Allow the user to create and save a new sleep log.

Example:

`22 Sep → No sleep log → Create Mode`

#### 3. Selecting a Date With an Existing Sleep Log

When the user selects a date:

* Check whether a sleep log already exists for that date.
* If a sleep log exists:

  * Load that sleep log.
  * Open it in **Edit Mode**.
  * Allow the user to update and save the existing record.

Example:

`21 Sep → Sleep log exists → Edit Mode`

#### 4. Do NOT Automatically Open the Latest Record

Important:

Opening the **Log Sleep** tab must NOT automatically select or load the most recent sleep record.

Do not use logic such as:

* latest sleep log
* last logged sleep
* most recent record
* first record from sleep history

to automatically initialize the edit form.

The selected date should determine whether the form is in Create or Edit mode.

### Multiple Entries Requirement

For this implementation, use the following business rule:

**Allow only ONE sleep log per calendar date.**

Do NOT allow multiple sleep records for the same date unless the existing backend/business requirements explicitly require multiple entries.

Therefore:

* Date has no record → Create new record.
* Date has one record → Edit existing record.
* Date already has a record → Do not create another duplicate record.

If the user tries to create another sleep log for a date that already has one, prevent duplicate creation and load/show the existing record in edit mode.

### Important Date Handling

Make sure the comparison is based on the **calendar date**, not the complete timestamp.

For example:

`2026-09-22 01:00`

and

`2026-09-22 22:00`

belong to the same calendar date if the app's sleep-log business rule treats them as the same sleep-log date.

Use the existing project's timezone/date handling conventions. Do not introduce a different timezone system unnecessarily.

The state should clearly distinguish between:

* Create Mode
* Edit Mode
* Loading

* No record found
* Saving

### Save Behavior

When saving:

**Create Mode**

* Create a new sleep log only if no record exists for the selected date.
* After successful creation, update the UI/history/state correctly.

**Edit Mode**

* Update the existing sleep log.
* Do not create a second record.
* Keep the selected date unchanged.
