# Step 9 — Prevent recurring bugs

This is VERY IMPORTANT.

The subscription implementation has previously developed bugs repeatedly after being fixed.

Do NOT apply temporary fixes.

Find the root cause.

Pay special attention to:

### Purchase stream

There must not be multiple subscriptions/listeners attached to the purchase update stream.

Do not initialize the purchase listener every time the subscription screen opens.

Initialize it once and dispose it correctly.

### Duplicate events

Prevent the same purchase event from being processed multiple times.

### Duplicate dialogs

A single purchase failure must display only one error.

A successful purchase must display only one success state/message.

### Widget lifecycle

Prevent:

* setState after dispose
* Bloc usage after dispose
* duplicate listeners
* duplicate stream subscriptions
* TextEditingController disposed errors
* navigation after widget disposal

### BLoC lifecycle

Do not create multiple SubscriptionBloc instances unnecessarily.

Use the existing dependency injection/provider structure.

### Navigation

Do not navigate multiple times after purchase.

Protect navigation against duplicate purchase callbacks.

### Restore

Restore must not create a new purchase.

Restore should only restore existing purchases and update the subscription state.

### Pending purchase

Do not show success until the purchase is actually completed/verified.

### Failed purchase

User cancellation must not be treated as a successful subscription.
