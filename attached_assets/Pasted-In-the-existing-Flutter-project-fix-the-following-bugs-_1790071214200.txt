* User opens **Add New Assignment**.
* User does NOT select a due date.

* When the user taps **Save/Create Assignment** without selecting a due date, validation must happen before submitting.

  **"Choose a due date"**

### Bug 2 — Estimated hours does not accept decimal values

Current behavior:

* In **Estimated Hours**, user enters a decimal value such as:

  * `2.5`
  * `1.5`
  * `0.5`
  * `10.75`
* The app shows:
  **"Enter 1 to 100 hours"**
* Decimal values should be valid.

Required behavior:

* Estimated Hours must accept numeric values from **1 to 100**, including decimal values.
* Valid examples:

  * `1`
  * `1.5`
  * `2.5`
  * `10.25`
  * `50.5`
  * `100`
* Invalid examples:

  * `0`
  * `0.5`
  * `100.1`
  * `101`
  * negative numbers
  * empty value
  * non-numeric text

Use proper numeric parsing, for example `double.tryParse()`, instead of integer parsing such as `int.tryParse()`.

Validation should follow:

```text
hours != null
AND
hours >= 1
AND
hours <= 100
```

Do not round or convert valid decimal values into integers.
