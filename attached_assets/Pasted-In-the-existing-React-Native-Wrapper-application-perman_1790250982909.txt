In the existing **React Native + Wrapper** application, permanently fix the validation issue in **Trusted Contact → Add New Contact**.

### Bug

When adding a new Trusted Contact:

* Email address format is not validated correctly.
* Phone number format is not validated correctly.
* Invalid values can sometimes pass validation.
* The issue has been fixed before but keeps reopening, so do a complete root-cause fix instead of a temporary UI-only fix.

### Required behavior

#### 1. Email validation

Validate the email before allowing the Trusted Contact to be saved.

Reject examples such as:

* `test`
* `test@`
* `@gmail.com`
* `test@gmail`
* `test..test@gmail.com`
* `test @gmail.com`
* empty email

Accept normal valid formats such as:

* `test@gmail.com`
* `john.doe@example.com`

Do not rely only on keyboard/input type. Perform actual validation in the form logic.

#### 2. Phone number validation

Validate the phone number before allowing the Trusted Contact to be saved.

Requirements:

* Reject empty phone numbers.
* Reject alphabetic characters.
* Reject invalid characters.
* Reject obviously invalid/incomplete phone numbers.
* Handle the phone number format already expected by the existing application/backend.
* Preserve the existing country-code behavior if the app already supports country codes.
* Do not create a new incompatible phone-number format.

Use a proper phone-number validation approach rather than checking only whether the field contains digits.

### 3. Validation must happen before API/database submission

The save flow must be:

User enters data
→ Validate fields
→ Show validation error
→ Stop submission if invalid
→ Only submit to backend when all required fields are valid

Invalid data must NEVER reach the API/database.
