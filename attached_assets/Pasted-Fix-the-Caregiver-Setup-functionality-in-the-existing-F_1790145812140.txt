### Bug 1 — Accepted caregiver not appearing in Active Caregivers

Flow:

1. User invites a caregiver.
2. Caregiver receives the invitation.
3. Caregiver accepts the invitation.
4. The invitation status changes to `ACCEPTED`.
5. However, the caregiver's name does NOT appear in the inviter's **Active Caregivers** list.
6. The same caregiver still appears in the **Invitations** section with status `ACCEPTED`.

Expected behavior:

* Once a caregiver accepts an invitation, that caregiver must immediately appear in **Active Caregivers**.
* The accepted invitation should no longer be treated as a pending invitation.
* If the existing product design intentionally keeps accepted invitations in the Invitations history, it may remain there, but it must NOT be considered an active/pending invitation.
* Active Caregivers must be based on the actual caregiver access/membership state, not only on invitation status.

### Bug 2 — Removed caregiver comes back after relogin

Flow:

1. User has an active caregiver.
2. User removes/revokes that caregiver's access.
3. The caregiver disappears from Active Caregivers.
4. User logs out.
5. User logs in again.
6. Sometimes the removed caregiver appears again in **Active Caregivers**.

Expected behavior:

* Once caregiver access is removed/revoked, that caregiver must NEVER appear in Active Caregivers after logout/login, app restart, refresh, or reopening the screen.
* Revoked access must be persisted in the backend/database.
* Active Caregivers must always be calculated from the current persisted access state.
* Do not rely only on cached BLoC state, local state, previously loaded lists, or invitation records.
