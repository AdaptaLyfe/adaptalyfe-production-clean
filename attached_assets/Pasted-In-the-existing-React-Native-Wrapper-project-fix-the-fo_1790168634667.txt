### Current issue

**Sleep Routine → Log Sleep**

The form currently contains fields such as:

* Sleep Date
* Bed Time
* Time Fell Asleep

There is **no Wake Date**.

This causes incorrect validation.

Example:

* Sleep Date: September 23

The app currently treats both times as being on the same date and shows:

**"Wake time cannot be less than sleep time."**

But 8:00 AM normally means the user woke up the **next morning**, September 24.

Wake Time: 8:00 AM

# Correct Date + Time Validation

Do NOT compare only the time values.

Combine the selected date and time into complete DateTime values.

For example:

```text
Sleep Date + Time Fell Asleep
Wake Date + Wake Time
```

Then compare the complete DateTime values.

### Valid example

```text
Sleep Date: Sept 23
Time Fell Asleep: 10:30 PM

Wake Date: Sept 24
Wake Time: 8:00 AM
```

Result:

**Valid**

### Invalid example

```text
Sleep Date: Sept 23
Time Fell Asleep: 10:00 PM

Wake Date: Sept 23
Wake Time: 9:00 PM
```

Result:

**Invalid**

Show the existing validation error because the wake time is actually before the sleep time.

### Another valid example

```text
Sleep Date: Sept 23
Time Fell Asleep: 10:00 PM

Wake Date: Sept 24
Wake Time: 9:00 PM
```

This is technically valid because the selected Wake Date is the next day.

The validation must use the selected dates rather than assuming that Wake Date is always the same date or always the next date.

---

# Date Selection Rules

Implement sensible validation:

1. Wake Date must not be earlier than Sleep Date.
2. If Wake Date == Sleep Date:

   * Wake Date + Wake Time must be greater than Time Fell Asleep.
3. If Wake Date > Sleep Date:

   * Compare the complete DateTime values.
   * Wake Time can be earlier than the sleep time because it is on a later date.
4. Do not automatically change the user's selected Wake Date.
5. Preserve the selected Wake Date when editing an existing sleep record.
6. When creating a new record, provide a sensible default Wake Date based on the existing sleep flow, but allow the user to change it.
7. Handle midnight correctly.
8. Handle 12 AM / 12 PM correctly.
9. Prevent invalid dates from being submitted.
