In the existing Flutter application, permanently fix the **Your Dashboard → Customize** skill module customization issue.

### Current Bug

In **Your Dashboard → Customize**:

* When a user enables a previously disabled skill module, then navigates back to **Your Dashboard**, the newly enabled module is not shown.
* When a user disables an already enabled skill module, then navigates back to **Your Dashboard**, the disabled module is still shown.
* The customization appears to change in the Customize screen, but **Your Dashboard does not reflect the latest configuration**.
* The bug has reopened multiple times, so do not apply only a UI-level workaround. Find and fix the root cause.

### Required Behavior

The selected skill modules in **Customize** must be the single source of truth for what is displayed on **Your Dashboard**.

When the user:

1. Opens **Your Dashboard → Customize**.
2. Enables or disables one or more skill modules.
3. Saves/applies the customization.
4. Returns to **Your Dashboard**.

The dashboard must immediately display the exact latest customization:

* Enabled module → MUST be visible.
* Disabled module → MUST NOT be visible.
* Multiple changes → ALL changes must be reflected.
* No stale/previous module configuration should remain.

### Root Cause Investigation

Before modifying code, trace the complete data flow:

**Customize UI → selected modules → state/BLoC/provider → repository/service → local/backend persistence → Dashboard → dashboard module filtering/rendering**

Check for:

* Separate or duplicated state between Customize and Dashboard.
* Dashboard using cached/old skill module data.
* BLoC/state not being refreshed after returning from Customize.
* Incorrect `Navigator.pop()` result handling.
* Missing reload after customization.
* Async save completing after the Dashboard starts rebuilding.
* Dashboard using default module configuration instead of the saved configuration.
* Incorrect skill/module IDs or name comparison.
* Boolean enabled/disabled values being inverted.
* `setState()` updating Customize but not the actual persisted state.
* Race conditions between save and dashboard reload.
* Widget lifecycle issues such as `initState()` loading data only once.
* `BlocBuilder`, `BlocListener`, `FutureBuilder`, Provider, or repository cache not receiving the updated state.
* Any other location where the old configuration can overwrite the newly saved configuration.

Fix the architecture/data flow so that there is one reliable source of truth for dashboard customization.

* Persist the latest configuration correctly.
